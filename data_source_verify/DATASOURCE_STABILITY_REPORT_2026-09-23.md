# 数据源稳定性与实时性专项核查报告

- **核查对象**：`WeStockProvider`（westock.exe → westock-data 技能），即 stock-simulator 生产环境实际依赖的外部行情源，提供实时行情 / K线 / 基本面 / 交易日历。
- **核查时间**：2026-09-23 14:24–14:26（实时探针）+ 运行日志回溯（2026-09-22 12:09 至 2026-09-23 09:31）。
- **核查执行**：实时探针 `data_source_verify/probe.py`（缓存隔离到临时目录，不扰动在线系统）+ 运行日志解析 `data/scheduler.log`、`data/live_run.log`。
- **数据口径声明**：⚠️ **系统自 2026-09-22 12:09 起运行，累计仅约 1.5 天日志，代码层无任何可用率/时延/成功率监控埋点，更无 3 个月历史监控数据。** 因此本报告"实测数据"均来自**本次现跑探针 + 现有运行日志**；模板要求的"近 3 个月监控、MTBF、MTTR、灾备切换成功率、多节点一致性"等**历史/基础设施类指标，在系统中尚不存在，本报告一律如实标注为"缺口/未采集"，绝不编造。

## 一、稳定性核查

### 1.1 服务可用性

**实测窗口**：2026-09-23 14:24–14:26，对 8 只标的循环发起 16 次 `westock quote` 调用 + 10 路并发 10 次 + 同标的 6 连发（共 32 次 CLI 调用）。

| 指标 | 实测值 | 说明 |
|---|---|---|
| 服务可用率 | **100.0%**（32/32 成功） | 串行 16/16、并发 10/10、突发 6/6 全成功 |
| 超时占比 | **0%** | 单次 CLI 超时阈值 45s，无超时 |
| 报错占比 | **0%**（returncode≠0） | 无执行失败 |
| 连接失败占比 | **0%** | 未出现 westock CLI 缺失/启动失败 |
| 单 call 时延 min / p50 / p95 / max | 2.29s / **2.71s** / 3.37s / 3.52s | 串行稳定，网络+CLI 启动开销为主 |
| 峰值时段 | 缺口 | 仅 1.5 天日志，无历史峰值时段统计 |

> 结论：在当前探测窗口内，westock 源**可用性良好、时延稳定（p50≈2.7s）**，无超时/报错/连接失败。但样本时长过短，**无法据此推断长期可用率**，需持续监控（见风险 R6）。

### 1.2 数据质量稳定性

| 维度 | 实测结果 | 风险等级 |
|---|---|---|
| 实时价缺失率（运行时） | **5/5 = 100%** 持仓 `现价=0.000` | 🔴 严重 |
| 落库空值率 | `data/live_prices.json` 实测为 `{}`（2 字节，空库） | 🔴 严重 |
| 重复数据占比 | 读取一致性 **100%**（同标的 5 次缓存读均返回 4.34，价格一致） | 🟢 正常 |
| 数值偏差率 | 单源无多副本可比对；缓存读一致性 100% | 🟢 正常 |
| 多节点/多副本一致性 | 系统为单实例单源，**无多副本**；仅缓存读一致性可证 | ⚪ 不适用 |

> **核心缺陷（R1）**：2026-09-22 收盘流程实测出现**全部持仓现价=0.000、实时价快照落库为空**。根因为实时价获取链路（`simulator._live_prices()` / `pnl._current_prices()`）直接采用 `get_quote().price`，**未串联 `MarketFeed.validate_quote` 校验闸门**，对源端返回的 0 / 空 / 异常值无防御性拦截，异常行情直接穿透落库。该系统已具备 `MarketFeed` 清洗闸门（可拒绝 `price<=0`/`NaN`/涨跌停倒置/时间戳回退/重复），但**仅用于单元测试，未接入实时价刷新与落库路径**。

### 1.3 容灾恢复能力

| 维度 | 现状 | 风险 |
|---|---|---|
| 备用链路 | **无**（仅 westock 单 CLI 依赖） | 🔴 |
| 灾备节点 | **无** | 🔴 |
| 故障自动切换 | **无**（无健康检查/哨兵切换）；`scheduler` 外层 `while` 仅重启自身进程，不切换数据源 | 🔴 |
| 数据备份 | 唯一"备份"= 本地 `data/.westock_cache.json`（TTL 分桶：fund 7d / quote 1d / close 7d / idx 7d / cal 30d） | 🟡 |
| MTTR（平均恢复时间） | **实测 1 次中断恢复≈2h03m**（见 1.4）；无 SLA、无自动告警 | 🔴 缺口 |
| MTBF（平均无故障时间） | **缺口**：累计在线约 1.5 天，仅观测到 1 次守护进程中断，样本不足，无法计算 | ⚪ 缺口 |

> 可恢复性：缓存文件损坏/过期后需重新触网抓取（首跑全市场预热 677s）。单缓存文件为单点，损坏即全量失效。

### 1.4 并发承载能力

**实测**：10 路并行 `westock quote` 突发。

| 指标 | 串行（1 路） | 10 路并行 | 退化 |
|---|---|---|---|
| 单 call 时延 p50 | 2.71s | 7.9s–14.8s（中位≈11.3s） | **≈4.2×** |
| 有效 QPS | ≈0.37 | **0.615** | — |
| 请求成功率 | 100% | 100% | 无丢数 |
| 限流（429） | — | 6 连发同标的未触发；代码已知 429 风险并内置重试退避 | 🟡 |

> **并发瓶颈（R3）**：westock 为**单 CLI 进程 + 串行网络、无连接池**，并发请求互相阻塞，10 路并行时延退化约 4 倍，有效吞吐仅 0.615 QPS。**无丢数**（成功率 100%），瓶颈在"单 CLI 串行化"而非丢包。佐证：全市场 800 只并行预热耗时 **677s（≈1.18 只/s）**。

## 二、实时性核查

### 2.1 全链路时延（采集 → 清洗 → 入库 → 接口输出）

| 环节 | 实测耗时 | 说明 |
|---|---|---|
| ① 采集（westock CLI 网络往返） | **2.71s（p50）** | 全链路最大瓶颈 |
| ② 清洗（`MarketFeed.validate_quote`） | **0.68 µs** | 可忽略，但**当前未串联到实时价落库路径**（见 R1） |
| ③ 入库（`get_quote` 解析+缓存写） | 首触 **2.50s** / 缓存命中 **20µs** | 首触含采集；命中为纯本地写 |
| ④ 接口输出（`get_quote` 缓存读） | **20µs** | 缓存命中即时 |
| **端到端（首次 / 缓存命中）** | **≈2.7s / <0.1ms** | 命中后实时性极佳 |

> 接口覆盖时延：K线(日,20) 2.57s；交易日历 2.66s；沪深300 成分 2.66s（300 只）；基本面 8.39s（profile+finance+quote+kline 四并行）。

### 2.2 更新时效

| 维度 | 实测/现状 | 说明 |
|---|---|---|
| 盘中刷新频率（标称） | 每 **60s**（`scheduler.REFRESH_SEC=60`） | 设计值 |
| 盘中刷新频率（实测） | 均值 **60.1s**、min 0.0s*、max 62.0s（128 条记录） | 与标称吻合，节奏稳定 |
| 刷新连续时段 | **12:09:28 – 14:16:40**（约 2h07m） | 之后守护进程停止 |
| **交易时段空窗** | **14:16:40 → 16:19:10 重启（约 2h03m 无刷新）** | 🔴 实时性中断（R4） |
| 增量漏更/错更 | 持仓现价=0.000 即"错更/漏更" | 🔴 与 R1 同源 |

> \* min 0.0s 为日志中一条损坏行（"新：5 只持仓"，无前缀时间戳）导致的解析伪影，非真实 0 间隔；其余间隔稳定在 60–62s。

### 2.3 时效准确性

| 维度 | 现状 | 风险 |
|---|---|---|
| 源端业务时间戳 | westock `quote.time` 字段实测仅返回**日期级**（`"2026-09-23"`），**无日内/时分秒精度** | 🟡（R5） |
| 入库时间戳 | 系统以本地 `updated_at = datetime.now()` 记录抓取时刻 | 🟢 |
| 超时效阈值数据占比 | 缺口（无时效阈值定义与统计） | ⚪ 缺口 |
| 过期数据清理机制 | 依赖缓存 TTL 分桶（quote 1d / close 7d / fund 30d …）；无独立"过期清理"任务 | 🟡 |

> 因源端 `time` 仅到"日"，**无法用源时间戳精校"业务时刻 vs 采集时刻"的日内时延**；时效判定应以本地抓取时刻 `updated_at` 为准（建议见 S5）。

### 3.3 优化建议（与风险点对应）

| 建议 | 对应风险 | 具体措施 |
|---|---|---|
| **S1 串联校验闸门 + 三级防御** | R1 | 在 `simulator._live_prices()` / `pnl._current_prices()` 接入 `MarketFeed.validate_quote`；对 `price<=0/NaN/非正` 拦截并回退；防御链：源实时价 → 缓存兜底 → 仍失败则**保留上次有效价并告警**，严禁 0 落库。 |
| **S2 增加备用数据源/兜底** | R2 | 实现 `MarketProvider` 优先级的故障切换（第二行情 CLI 或公开 API）；至少对 `MockProvider` 做"极端不可用"兜底并明确标注"演示数据"。 |
| **S3 突破并发瓶颈** | R3 | westock 提供器改为常驻子进程/连接池（避免每次 `subprocess`）；或改用批量接口；预热并发度自适应 + 429 熔断（已有退避，补熔断）。 |
| **S4 守护进程健康检查** | R4 | `scheduler` 增加心跳（每 5min 写心跳文件）+ 独立看门狗检测超时即重启；盘中刷新中断即时告警（邮件/Webhook）。 |
| **S5 时效以本地时刻为准** | R5 | 以 `updated_at`（本地抓取时刻）作为时效主依据；记录"采集→入库"时延；源端 `time` 仅作日期参考。 |
| **S6 监控埋点** | R6 | 在 westock 提供器与 scheduler 增加指标采集（可用率/时延 p50,p95/成功率/刷新间隔），落盘 `metrics.jsonl` + 每日汇总，支撑 MTBF/MTTR/可用率趋势与 3 个月监控积累。 |
| **S7 缓存分级 + 容灾** | R7 | 区分"日内实时价"（TTL 短，每分钟强制刷持仓价）与"基本面/历史"（TTL 长）；缓存文件加校验和 + 定期备份，损坏自动重建。 |
